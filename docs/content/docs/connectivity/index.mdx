## Introduction

This documentation covers all available connectivity methods, regional endpoints, latency specifications, and enterprise connectivity programs.

## Connectivity Decision Matrix

### Choose Public API if:
- Trading volume < 10,000 orders/day
- Latency requirements > 50ms acceptable
- No dedicated infrastructure budget
- Getting started or testing

### Choose VPN if:
- Trading volume 10,000-100,000 orders/day
- Latency requirements 5-50ms
- Need encrypted access from multiple locations
- Regulatory requirement for secure channels

### Choose Dedicated if:
- Trading volume 100,000-1,000,000 orders/day
- Latency requirements < 1ms
- Running algorithmic strategies
- Need guaranteed bandwidth

### Choose Colocation if:
- Trading volume > 1,000,000 orders/day
- Latency requirements < 100us
- High-frequency trading strategies
- Market making operations

## Getting Started

### 1. Public API Access

Instant access via public endpoints:

```bash
# REST API
curl https://api.lux.exchange/v1/health

# WebSocket
wscat -c wss://ws.lux.exchange/v1

# gRPC
grpcurl grpc.lux.exchange:9760 lx.dex.v1.TradingService/GetMarkets

# FIX 4.4
# Connect to fix.lux.exchange:9880
```

**Global Endpoints (GeoDNS Load Balanced)**

| Protocol | Endpoint | Port | Description |
|----------|----------|------|-------------|
| REST | `https://api.lux.exchange` | 443 | Primary REST API |
| WebSocket | `wss://ws.lux.exchange` | 443 | Real-time feeds |
| gRPC | `grpc.lux.exchange` | 9760 | High-performance RPC |
| FIX | `fix.lux.exchange` | 9880 | Financial Information eXchange |
