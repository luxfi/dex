# Orderbook Engine

The LX DEX orderbook engine is designed for ultra-high performance trading with multiple backend options.

## Overview

The matching engine achieves:
- **434M+ orders/sec** with GPU acceleration
- **2ns latency** on Apple Silicon MLX
- **487ns latency** on pure CPU
- **Zero-copy** trade recording

## Architecture

```
+----------------------------------------------------------+
|                    Order Flow                             |
+----------------------------------------------------------+
|  Client Order                                             |
|       |                                                   |
|       v                                                   |
|  [Validation] ---> [Risk Check] ---> [Matching Engine]   |
|                                            |              |
|                                            v              |
|                                      [Order Book]        |
|                                       /         \        |
|                                 [Bids]           [Asks]  |
|                                 B-Tree           B-Tree  |
|                                            |              |
|                                            v              |
|                                      [Trade Buffer]      |
|                                      (Circular, Lock-free)|
+----------------------------------------------------------+
```

## Order Book Structure

Each trading pair maintains a separate order book with optimized B-tree structures:

```go
type OrderBook struct {
    Symbol      string
    Bids        *BTree[PriceLevel]  // Sorted high to low
    Asks        *BTree[PriceLevel]  // Sorted low to high
    Orders      map[string]*Order   // O(1) order lookup
    TradeBuffer *CircularBuffer     // Zero-copy trades
}

type PriceLevel struct {
    Price   int64           // Integer cents
    Orders  []*Order        // FIFO queue
    Volume  int64           // Total volume at level
}
```


## Time in Force

| TIF | Description | Behavior |
|-----|-------------|----------|
| GTC | Good Till Cancelled | Remains until filled or cancelled |
| IOC | Immediate or Cancel | Fill what's possible, cancel rest |
| FOK | Fill or Kill | Fill entirely or cancel entirely |
| DAY | Day Order | Expires at end of trading day |

```go
order := &types.Order{
    Symbol:      "BTC-USD",
    Type:        types.Limit,
    Side:        types.Buy,
    Price:       "50000.00",
    Size:        "1.0",
    TimeInForce: types.IOC,
}
```

## Matching Algorithm

### Price-Time Priority

Orders are matched using price-time priority (FIFO at each price level):

```go
func (book *OrderBook) Match(incomingOrder *Order) []*Trade {
    var trades []*Trade
    
    // Get opposing side
    levels := book.GetOpposingSide(incomingOrder.Side)
    
    for _, level := range levels {
        if !level.CanMatch(incomingOrder) {
            break
        }
        
        for _, restingOrder := range level.Orders {
            trade := book.ExecuteTrade(incomingOrder, restingOrder)
            trades = append(trades, trade)
            
            if incomingOrder.RemainingSize == 0 {
                return trades
            }
        }
    }
    
    // Add unfilled portion to book
    if incomingOrder.RemainingSize > 0 {
        book.AddToBook(incomingOrder)
    }
    
    return trades
}
```

### Execution Flow

1. **Validation**: Check order parameters
2. **Risk Check**: Verify margin/balance
3. **Price Match**: Find matching orders
4. **Trade Execution**: Execute matched trades
5. **Book Update**: Add remainder to book
6. **Notification**: Publish trade events

## Performance Engines

### Pure Go Engine

Default engine with excellent portability:

```go
book := lx.NewOrderBook("BTC-USD", lx.WithGoEngine())
```

Performance:
- Throughput: 1M+ orders/sec
- Latency: ~500ns
- Memory: ~100 bytes per order

### C++ Engine

High-performance engine with SIMD optimizations:

```go
book := lx.NewOrderBook("BTC-USD", lx.WithCppEngine())
```

Performance:
- Throughput: 30M+ orders/sec
- Latency: ~25ns
- Requires: CGO enabled

### GPU/MLX Engine

Massive parallelization on Apple Silicon:

```go
book := lx.NewOrderBook("BTC-USD", lx.WithMLXEngine())
```

Performance:
- Throughput: 434M+ orders/sec
- Latency: ~2ns
- Requires: Apple Silicon M-series

### Auto-Selection

Automatically choose best available engine:

```go
book := lx.NewOrderBook("BTC-USD", lx.WithAutoEngine())
```

Selection order:
1. GPU/MLX (if Apple Silicon available)
2. C++ (if CGO enabled)
3. Pure Go (fallback)

## Memory Management

### Object Pooling

Reuse order objects to minimize allocations:

```go
var orderPool = sync.Pool{
    New: func() interface{} {
        return &Order{}
    },
}

func GetOrder() *Order {
    return orderPool.Get().(*Order)
}

func PutOrder(order *Order) {
    order.Reset()
    orderPool.Put(order)
}
```

### Lock-Free Trade Buffer

Zero-copy circular buffer for trades:

```go
type CircularTradeBuffer struct {
    buffer  []Trade
    head    atomic.Uint64
    tail    atomic.Uint64
    mask    uint64
}

func (b *CircularTradeBuffer) Push(trade *Trade) {
    pos := b.head.Add(1) - 1
    b.buffer[pos & b.mask] = *trade
}
```

## Best Practices

1. **Use object pooling** for high-frequency trading
2. **Batch orders** when possible for better throughput
3. **Choose appropriate engine** based on latency requirements
4. **Monitor memory** to avoid GC pauses
5. **Use atomic operations** for counters and flags
